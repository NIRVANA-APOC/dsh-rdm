## Scope bounds

* Candidates are HTTP(S) only. Cross-protocol sources (FTP/S3/torrent) remain
  future protocol work; this is why V4 covers Metalink/HTTP and `.meta4`
  discovery but not FTP/torrent source execution.
* `race`/`failover` mix bytes only with a strong shared content identity
  (`expectedSha256`, server SHA-256/Content-Digest, or equal size + strong
  ETag); otherwise the kernel reports `select` and a `source` event.
* `select`/`hedge` never mix bytes: they choose or commit to one source.
* A multi-file `.meta4` requires `metalinkFile`; single-file documents resolve
  automatically. DRM/live media and site extractors are out of scope.
